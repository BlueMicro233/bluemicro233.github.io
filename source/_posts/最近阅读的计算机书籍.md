# 计算机基础
## 程序的本质 ——《计算机程序的构造和解释》
《计算机程序的构造和解释》（SICP）这本书是麻省理工学院 6.001 课程的教材，自 1980 年到 2008 年被持续使用。这本书利用 Lisp 编程语言介绍计算机程序的各种伟大思想，可谓是计算机科学领域的哲学书。

当代编程语言的 lambda 表达式、高阶函数、闭包、惰性求值、垃圾回收等特性就是在重新实现 SICP 里描述过的东西。

> MIT 现在改教 Python 了。同时 SICP 这门课在 [Berkeley](https://cs61a.org/fa26/) 和[南京大学](https://sicp.pascal-lab.net/2026/)等地的课程也正以 Python 的方式呈现。不过，个人认为 SICP 还是搭配 Lisp 更对味一点，可能因为我是以一种考古学的视角去看待的。

### 重新理解递归
我是先学过了 C 和 C# 再去看的 SICP，于是非常有新鲜感。我们知道，如果你尝试在 C（或 C++ / C# / Java）里实现一个**迭代**计算 Fibonacci 通项的程序：
```c
int fib(int n) {
    int a = 0, b = 1;
    for (int i = 0; i < n; ++i) {
        int next = a + b;
        a = b;
        b = next;
    }
    return a;
}
```
而 Lisp 里是没有显式寄存器变量的，同样的程序会写成：

```lisp
(define (fib n)
  (fib-iter 1 0 n))

(define (fib-iter a b count)
  (if (= count 0)
      b
      (fib-iter (+ a b) a (- count 1))))
```

这不是递归吗？怎么迭代了？我们知道递归计算 Fibonacci 通项的时间复杂度是指数级的 $O(\phi^n), \phi = \frac{1 + \sqrt{5}}{2}$，而实际上本文的这个 Lisp 程序的时间复杂度是线性的 $O(n)$。

可以看出它没有直接把 $F(n) = F(n - 1) + F(n - 2)$ 这个递归的公式翻译上去，而是在线性地更新状态 `(a b count)` 到 `(a+b a count-1)`，最后 `(= count 0)` 时候返回，并没有产生 Fibonacci 调用树。也就是说递归语法和递归过程其实并不是一回事，递归语法可以产生迭代过程。这是读完 SICP 第一章就能领会的 —— **直接看到程序的形式和本质的联系**。

### 独特的程序结构
国内数据结构课很多使用的是严蔚敏老师的《数据结构（C 语言版）》紫皮书，它经常被诟病讲解晦涩和部分内容非主流（比如**“广义表”**、静态链表）。其实这本书里说的广义表就是 `(a b (c d) (e f g))` 这样的结构，Lisp 语言的表达式本身就是一种广义表（它叫 S-expression），从上面贴出的 Lisp 源码就可以看出这种独特的结构。

而课上讲的 `Head()` 和 `Tail()` 就是 Lisp 里的 `car` 和 `cdr`，~在反直觉的同时又有种拙劣的模仿感233~

> 因为 `Head()` 是取表头元素，所以直觉告诉我们 `Tail()` 是取表尾元素，但实际上这本书规定的是去掉表头之后取整个表，这和 Lisp `cdr` 的功能一致。
>
> 所以这本书讲“广义表”的迷惑之处就在于：在面向 C 程序设计的课程中，引入了一套与 Lisp 列表处理高度相关的抽象，却没有充分地建立两者之间的概念桥梁。

### 解释器的魔法
对于程序语言本身，SICP 还介绍了 eval-apply 循环，它揭示了**一个程序语言可以解释它自己**，听起来像魔法。这其实就是解释器（interpreter）的核心—— `eval` 负责解释表达式的含义，决定如何求值；而 `apply` 就负责执行相应的求值计算。

## 击穿黑盒 ——《深入理解计算机系统》
此书就是大名鼎鼎的 **CSAPP (Computer Systems: A Programmer’s Perspective)** ，同时是[CMU 15-213 课程](https://www.cs.cmu.edu/~213/)的教材。

这本书主要就是介绍计算机底层基础，把二进制、汇编、体系结构、链接和装载、虚拟内存、OS、网络这些知识都放进了一本书，相当于把几门零散的计算机核心专业课都拉通来整理了一遍，让人形成系统认识。

> 具体的专业课程是一定比这本书介绍的相关主题更深入的（例如 jyyOS, CS61C 等）。而 CSAPP 以程序员的视角把基础知识串起来，能起到很好的预习作用。

CSAPP 除了提供很多优质的小练习之外，还有几个著名的 Lab。这些 Lab 的难度很大，非常锻炼人，比如 Bomb Lab 就是让你使用 gdb 逆向一个二进制程序，通过研究反汇编来得到关卡的答案 ~否则这个程序就要爆炸！砰！~ ，我之前 [有一篇文章](https://bluemicro233.github.io/post/CSAPP-Bomb-Lab-%E5%88%9D%E6%8E%A2/) 尝了下咸淡，确实挺有意思的。

如果感兴趣或者时间充裕，这几个 Lab 是不容错过的，它们也是 CSAPP 的精髓。

### 工作在具体的机器上
看这个例子：

```c
int run() {
  return 1145141919 * 1919810;
}
```

理论上 `run()` 会计算出一个很大的数，但实际上控制台输出的是 `-1412353538`，并且在这之前，编译器就在抱怨了：

```plaintext
Overflow.c:4:23: warning: overflow in expression; result is -1'412'353'538
      with type 'int' [-Winteger-overflow]
    4 |     return 1145141919 * 1919810;
      |            ~~~~~~~~~~~^~~~~~~~~
1 warning generated.
```

这是 32 位整数溢出的结果，如果你经常看科普视频或者评论区，一定或多或少了解过，而 CSAPP 就会从底层（甚至会提及抽象代数）出发解释这些现象的原因和规律。

由于现在的框架过于抽象、电脑内部过于精巧和复杂，以至于我们很多时候都忘了软件是真真实实地跑在粗犷的数字电路器件上的。数学是理想，物理是现实，为了实现计算，必要的设计限制一定是存在的，而我们至少要对这些限制知情，以更好地使用机器。
